# Hackathon mode (Tectonic Hackathon, KBC track)

We have about 4 hours. A working demo matters more than code quality. These rules override
conflicting guidance elsewhere, including my global CLAUDE.md.

## Priorities

1. One happy path that works end to end and can be demoed live.
2. It looks clean on a projector.
3. Everything else.

## How to work

- Build the simplest thing that works. No extra abstractions (interfaces, repositories, service
  layers, DTOs) unless asked.
- Hardcode and mock freely: fake external APIs, skip edge cases, validate only what the demo
  needs.
- Do NOT write or run tests unless explicitly asked. This overrides any testing instruction
  anywhere else.
- Keep changes small and local. Teammates work in parallel, so do not refactor or reformat files
  you were not asked to touch.
- Do not add composer or npm packages without asking first.
- If a fix fails twice, stop and explain the problem instead of trying bigger and bigger fixes.

## Running the app

The app runs in ddev at https://tectonic-hackaton.ddev.site. Never run `ddev start`, `ddev
restart` or `ddev stop` yourself, tell me and I will.

Everything runs inside the container. Never call `php`, `composer`, `npm` or `artisan` directly
on the host.

- `ddev artisan ...`, `ddev composer ...`, `ddev php ...`, `ddev npm ...`.
- `ddev npm run dev` serves Vite on https://tectonic-hackaton.ddev.site:5173,
  `ddev npm run build` builds.
- `ddev npm run check` formats and lints the frontend, `ddev npm run check:fix` fixes it,
  `ddev npm run types:check` is tsc. The tool is vite-plus (`vp`), not eslint or prettier.
- `ddev composer lint` is Pint for PHP.
- Node is pinned by `.nvmrc`, which is what `nodejs_version: auto` in the ddev config reads.

## Stack

Laravel 13, Inertia 3, React 19, TypeScript, Tailwind 4, Fortify for auth, Wayfinder for typed
routes. Installed from the official React starter kit, so login, register, password reset, 2FA,
passkeys and the settings pages already exist and need no work.

- Pages are `resources/js/pages/*.tsx` and resolve by filename. Drop a file in, no registration
  needed.
- The layout is chosen centrally by the switch in `resources/js/app.tsx`. Anything that is not
  `welcome`, `auth/*` or `settings/*` gets the sidebar layout automatically. Pass layout props
  with `Page.layout = { breadcrumbs: [...] }`, see `resources/js/pages/dashboard.tsx`.
- Sidebar nav items live in `resources/js/components/app-sidebar.tsx`.
- Never hand-write a URL. Import the generated helper: `import { dashboard } from '@/routes'`.
  `resources/js/routes`, `resources/js/actions` and `resources/js/wayfinder` are generated by the
  Vite plugin, so never edit them, and restart `ddev npm run dev` after adding a route.
- Reuse the shadcn components in `resources/js/components/ui` before building new UI. There are
  26 of them, including sidebar, sheet, dialog, dropdown-menu, select, sonner and input-otp. They
  are excluded from lint and formatting on purpose.
- Tailwind 4 is CSS-first. There is no `tailwind.config.js`, theme tokens live in
  `resources/css/app.css`.
- The React Compiler is on, so do not add `useMemo`, `useCallback` or `memo` by hand.
- Keep all LLM calls and prompts in one service class so prompts are easy to tweak.

## Data

- MySQL 8.0 in ddev, not SQLite. Migrate with `ddev artisan migrate`, reset with
  `ddev artisan migrate:fresh --seed`.
- Demo data lives in seeders, generated with Faker's `nl_BE` locale for Belgian names and
  `iban('BE')`.
- Never use or ask for real customer data.

## Domain

- The client is KBC, a Belgian bank. Judges care about privacy and GDPR, security, and
  explainability.
- When AI suggests or decides something, show the reasoning in the UI and keep a human in the
  loop.
- All UI copy in English (plain, informal "you"). Doppel speaks in the first person ("I") and in
  the past tense: he already lived the customer's month. Screens about Doppel (profile, settings)
  speak about "Doppel" in the third person. Never mix in Dutch.
- Fixed terms: "What Doppel saw" (the signals), "That's not me" (feedback), "No sale" (no-sale
  cards), "What if I…" (fork). Signals describe facts about "your account", never "I saw".
- In the base scenario Doppel lives the month as the customer is. Advice belongs on the action card,
  never in a diary line as if the customer already did it.
